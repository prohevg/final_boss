| Ограничение | Источник | Как отражено |

| Команда 40–60, эксперименты | Контекст | ADR-001 домены = команды; фиче-флаги (11.5) |

## 2. Структура (поверх концептуальной схемы А-04)

Диаграмма: [`d1_conceptual.png`](../../diagrams/d1_conceptual.png).
Детализация представлений: [А-14a…e](views/).

**Технологический стек (по слоям)**

| Слой | Решение | ADR |
|------|---------|-----|
| Клиент | iOS/Android (native), офлайн-журнал, адаптеры HealthKit/GFit/BLE | 006 |
| Edge | CDN+WAF провайдера (или общий Anycast), API-шлюз (Envoy/Gateway-api) + BFF (Go/Node) | 005 |
| Домены | 11 сервисов, Go/Kotlin/TypeScript (на выбор команд), K8s, HPA/KEDA | 001 |
| События | Kafka (self-managed, MirrorMaker между облаками), схемы в registry | 004, 011 |
| Данные | PostgreSQL (регион), Redis, OpenSearch, ClickHouse, S3-совместимое хранилище | 007, 008, 011 |
| PII | Выделенный PostgreSQL + KMS, журнал доступа | 003 |
| Вход | OIDC (IdP компании), JWT 15 мин, mTLS для партнёров | 009, 010 |
| Наблюдаемость | OpenTelemetry → Prometheus/Thanos, логи (агенты → Kafka → hot 14 дн → Parquet в S3), трассы | 012 |
| Инфраструктура | Terraform-модули, GitOps (ArgoCD), 3 региона + DR в резервном контуре | 002 |

**Данные в одном месте по доменам** (схема `d4_information.png`):
каждый домен владеет своими таблицами; внешние — только через события.
Региональность: `user_id → регион данных` определяет, в каком кластере
живут его строки (ADR-003).

**Ключевые контракты (публичные)**:
- Мобильный API: `/v1/workouts`, `/v1/feed`, `/v1/search`, … (версии, окно 2 версий)
- Партнёрский API: `/v1/refs` (deep link + атрибуция), `/v1/conversions`
- События: `workout.completed`, `achievement.earned`, `group.posted`,
  `promo.delivered`, `purchase.ref_*` (совместимость схем обязательна)

## 3. Адресация атрибутов качества (главная таблица этапа)

| Атрибут | Механизм | Компонент / ADR | Как измеряем |
|---------|----------|-----------------|--------------|
| **АК-1** Масштабируемая доступность | Буферизация пиков в Kafka + автоскейл по лагу (KEDA) | Challenges, Kafka (ADR-004) | lag ≤ 30 с на пике; ×10 за ≤ 3 мин |
| | Шардированные Redis-лидерборды с TTL | ADR-008 | обновление таблицы ≤ 10 с |
| | Приоритетная деградация (промо → подсказки → приём) | BFF, Notifications | приём результатов не прерывается |
| | 3 региона + GSLB + DRP, rolling-деплой | ADR-002, А-14d | 99,9 %; RTO ≤ 2 ч |
| **АК-2** Приватность и безопасность | Residency: PII-хранилище региона под KMS | ADR-003 | аудит: 0 обращений к PII вне контура |
| | Согласия версионируются, события очистки | FR-15, ADR-004 | выгрузка ≤ 30 дн, удаление ≤ 7 дн |
| | Зоны доверия, JWT 15 мин + step-up, mTLS | ADR-005/009/010, А-14e | попадание PII в логи = 0 (PII-фильтр) |
| | JIT-доступ инженеров с записью сессии | А-14e | 100 % сессий в журнале |
| **АК-3** Наблюдаемость | OTel в каждом сервисе, trace_id через HTTP и Kafka | ADR-012 | 100 % сервисов со спанами |
| | Единый дашборд инцидента (метрика→лог→трасса) | 15.6-пайплайн, А-14d | MTTD ≤ 5 мин, MTTR ≤ 30 мин |
| | Retention и классификация логов | ADR-012, 15.6 | hot 14 дн, холод — Parquet |
| **Доп.** Отзывчивость | BFF-сборка + кэш, региональные чтения | ADR-005 | p95 ≤ 300 мс |
| **Доп.** Офлайн | Локальный журнал + идемпотентная синхронизация | ADR-006 | 0 потерь при обрывах ≤ 24 ч |
| **Доп.** Стоимость | Классификация данных, автоскейл в ноль ночью | А-16 | $/MAU-месяц (цель: не растёт) |
