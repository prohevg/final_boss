# А-12. Сценарии использования приложения

> Этап 2 · Защита плана реализации. Актёры и потоки; альтернативные ветки
> приведены там, где они меняют архитектуру. Связь с ФТ — [А-02](../stage1-concept/02-functional-requirements.md).

## Актёры

| Актёр | Описание |
|-------|----------|
| **Участник** (любитель/профессионал) | Основной пользователь: тренируется, сравнивает, общается |
| **Ребёнок / представитель** | Несовершеннолетний: урезанный режим, согласие представителя |
| **Организатор** | Создаёт группу/челлендж/соревнование |
| **Приложения компании** | Внешний интегратор: приём deep link, отдаёт конверсию |
| **Региональный менеджер** | Размещает промо и контент региона |
| **Модератор** | Разбирает жалобы и очередь публикаций |
| **Инженер (SRE/поддержка)** | Диагностика по trace, выгрузка данных пользователя |

## Сценарии

### UC-01. Онбординг и согласия — актёр: Участник · FR-10, FR-15 · фаза 0
Основной поток: вход по SSO (или регистрация) → подтверждение даты
рождения → экран согласий (биометрия Art. 9 — отдельный флаг) → настройки
видимости по умолчанию (приватность по умолчанию — «только я») →
подключение телефона (HealthKit/Google Fit) → готово.
Альтернативы: *несовершеннолетний* → возрастной режим + согласие
представителя; *офлайн-вход* → анонимный профиль, привязка при первой
синхронизации (ADR-009).

### UC-02. Тренировка с устройством — актёр: Участник · FR-09, FR-12 · фаза 0
Старт тренировки → паринг BLE (ЧСС/SpO2) или данные телефона → запись
потока → финиш → локальное сохранение → синхронизация → события в Kafka
→ статистика и личные рекорды.
Альтернативы: *нет батареи/обрыв* → завершение из журнала, досчёт при
синхронизации; *аномальный поток* → пометка качества (T-11), включение
в сравнения после проверки.

### UC-03. Офлайн-тренировка «в диких местах» — актёр: Участник · FR-14 · фаза 0
См. КС-4: журнал на устройстве → пакетная синхронизация
(Idempotency-Key) → правило слияния при конфликте → события.
Альтернативы: *повторная отправка* → дедуп по ключу, без дублей;
*офлайн > 30 дней* → журнал хранится, старше — свёртка в сводку.

### UC-04. Сравнение с прошлым собой — актёр: Участник · FR-02 · фаза 0–1
Открытие статистики → срезы: «я сейчас vs я вчера/прошлой неделей»
(главный), «я vs регион», «я vs профи» → персональные рекорды →
разбор сегментов тренировки.
Альтернативы: *нет истории* → онбординг-сравнение с целевыми ориентирами.

### UC-05. Создание и жизнь группы — актёр: Организатор/Участник · FR-01 · фаза 1
Создание группы по интересу (тег, видимость) → роли (организатор,
модератор) → публикации → автофильтр Moderation → приглашения и
рекомендации похожих групп → совместные челленджи.
Альтернативы: *нарушение правил* → жалоба → очередь ревью (NFR-10),
блокировка публикации; *группа детей* → повышенный приоритет модерации.

### UC-06. Поиск людей и совместная тренировка — актёр: Участник · FR-03 · фаза 2
Фильтр (интересы/место/маршруты/«сейчас») → результаты Search →
предложение встречи (время, точка) → обе стороны получают уведомление →
совместная сессия.
Альтернативы: *статус «сейчас» выключен* → пользователь не в выдаче
«на сейчас» (приватность, FR-15); *пустая выдача* → расширение радиуса,
подсказки групп.

### UC-07. Уведомление друзьям об успехе — актёр: Участник · FR-06 · фаза 1
Рекорд/челлендж → публякация с учётом настроек видимости → Notifications
Hub (квоты, дедуп) → push друзьям → реакции в ленте.
Альтернативы: *пользователь в тишине* → квота выключена, доставка только
в ленту; *внешний push-провайдер недоступен* → ретраи по очереди.

### UC-08. Участие в массовом соревновании — актёр: Участник · FR-13 · фаза 2
Регистрация на старт → тренировка в режиме события → позиции шлюзуются
пачками → живые таблицы → финиш → итоги и медали.
Альтернативы: *пик ×10* → приоритетная деградация (КС-1, АК-1);
*подозрительный результат* → пометка «на проверке» до модерации.

### UC-09. Подсказка по инвентарю → покупка — актёр: Участник + Приложения компании · FR-04, FR-10 · фаза 3
Износ обуви по пробегу → подсказка «пора обновить» с товаром → deep link
(Commerce Bridge, источник `workout_hint`) → экран покупки в приложении
компании → возврат → событие конверсии → сверка атрибуции.
Альтернативы: *мост недоступен* → резервный баннер промо (B-03);
*пользователь закрыл приложение* → конверсия считается по возвращению.

### UC-10. План тренировок — актёр: Участник · FR-05 · фаза 3
Цель/ритм → план от Recommendations → расписание и напоминания →
выполнение (пометки из тренировок) → корректировка плана по прогрессу.
Альтернативы: *нет данных* → план от ориентиров онбординга; *офлайн* →
план в кэше клиента (NFR-06).

### UC-11. Размещение регионального промо — актёр: Региональный менеджер · FR-08, FR-11 · фаза 3–4
Кампания (регион, язык, сегмент, окно, лимит показов) → модерация
контента → подача Promo-движком по характеру тренировок (FR-08) →
A/B → конверсия через Commerce Bridge.
Альтернативы: *нет ML* → правила и ручные сегменты (фаза 3);
*перебор показов* → квота Notifications Hub защищает от B-02.

### UC-12. Управление приватностью и удаление данных — актёр: Участник + Инженер · FR-15 · фаза 0
Настройки видимости/согласий → отключение «сейчас» → выгрузка (≤ 30 дней)
или удаление (≤ 7 дней): события очистки во все домены, кэши и индексы
вычищаются, журнал операции.
Альтернативы: *запрос через поддержку* → личность подтверждается
step-up; *юридическое удержание* → частичное удаление с пометкой.

### UC-13. Модерация публикации — актёр: Модератор · NFR-10 · фаза 1
Жалоба/автофильтр → карточка (контент, история, риск) → решение
(пропустить/скрыть/предупредить) → обратная связь автору → блокировка
при рецидивах.
Альтернативы: *детский контент* → приоритетная очередь; *спорный
случай* → эскалация к арбитражу сообщества.

### UC-14. Диагностика инцидента — актёр: Инженер · NFR-07 · фаза 0
Алерт → дашборд инцидента (метрика → лог по trace_id → трасса) →
причина (квоты/релиз/внешний API) → откат/фикс → постмортем.
Альтернативы: *внешний провайдер лежит* → деградация по runbook
(ADR-010/ADR-009), следующий шаг — DRP (если регион, риск T-08).
