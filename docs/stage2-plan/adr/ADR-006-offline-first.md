# ADR-006: Offline-first захват тренировок

**Статус**: Принято · Этап 1
**Контекст**:
- Особенность 1: группы тренируются в «диких» местах без сети —
  потеря тренировки = прямое нарушение обещания продукта (КС-4).
- Данные устройств (BLE) идут потоком во время тренировки — обрыв
  связи не должен обрывать запись.
- Риск T-03: конфликты двух записей одной сессии, дубли при повторах.

**Решение**:
1. **Локальный журнал** на клиенте: тренировка пишется в локальное
   хранилище (append-only), включая нормализованные сэмплы устройств;
   метки времени — локальные, монотонные.
2. **`workout_id` генерирует клиент** (UUIDv7) — ключ идемпотентности
   с рождения.
3. **Пакетная синхронизация** при появлении сети: batch с
   `Idempotency-Key`; повтор того же batch → `200` с прежним результатом
   (без дублей).
4. **Правило слияния при конфликте** (две записи одной сессии, например
   телефон + часы): дистанция — максимум по интервалам, время — объединение
   непересекающихся интервалов, ЧСС — по более свежему источнику;
   результат версионируется (`merge_v2` — правило можно обновлять).
5. Журнал очищается только после подтверждения сервера; хранение — до
   30 дней (защита от долгих офлайнов); на устройстве — шифрование.
6. Обратная доставка состояния (обновления друзей, планы) — по
   «диффу» при подключении; офлайн-доступ к планам — кэш.

**Последствия**:
- (+) NFR-06 выполняется конструктивно: 0 потерянных тренировок при
  обрывах до 24 ч (критерий КС-4).
- (+) Синхронизация не зависит от мгновенной доступности сервера —
  АК-1 на клиенте.
- (−) Правила слияния — источник спорных случаев: сверка метрик
  «справедливости» в поддержку + возможность ручного пересчёта.
- (−) Сложность тестирования: матрица обрывов сети/батареи/убийства
  процесса — обязательный набор в CI (эмуляторы).
- (−) Локальное хранилиство — цель для физической кражи устройства:
  шифрование + опциональный PIN.
