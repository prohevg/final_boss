# ADR-011: Хранилища — управляемое по умолчанию, self-managed точечно

**Статус**: Принято · Этап 1
**Контекст**:
- Два провайдера с разными каталогами managed-сервисов (ADR-002):
  «управляемое» — дёшево в эксплуатации, но не везде одинаково.
- T-07: рост данных 15 → 200 ТБ (А-16) требует дешёвого холодного слоя.
- T-09: не заезжать в ловушку неэкспортируемых форматов.

**Решение** (таблица соответствия «задача → хранилище → как разворачиваем»):

| Задача | Хранилище | Модель |
|--------|-----------|--------|
| Оперативные данные доменов | PostgreSQL | управляемый, постер-реплика в регионе (резерв — managed-фолловер в DR) |
| Кэш, сессии, live-лидерборды | Redis | управляемый кластер; состояние — AOF/реплики |
| События и потоки | Kafka | **self-managed в каждом провайдере** (единые топики, MirrorMaker между облаками) — managed-аналоги в облаках несовместимы по семантике |
| Поиск | OpenSearch | управляемый (или self-managed, где нет) — один вариант версии в обоих облаках |
| Аналитика, сравнения | ClickHouse | управляемый там, где есть; иначе self-managed |
| Треки, медиа, холод (Parquet) | S3-совместимое объектное хранилище | управляемое провайдера; **конкурентноспособный формат** (Parquet/JSON) — экспорт в любое место |
| PII и согласия | PostgreSQL (выделенный инстанс) + KMS | отдельный контур (ADR-003) |

Правило выбора: **managed → если сервис есть в обоих провайдерах в
сопоставимой версии и экспортируем**; иначе self-managed в контейнерах
(общий helm/оператор = одна эксплуатационная модель).

**Последствия**:
- (+) Минимум «самого»: self-managed только Kafka (и опционально
  ClickHouse) — потому что семантика потоков важнее комфорта.
- (+) Экспортность: Parquet/S3, Postgres-совместимость — миграционные
  сценарии живы (T-09 закрыт), холод дешевеет годами (T-07).
- (−) Kafka на себе: руки SRE + бэкапы/мониторинг — закрыто шаблоном
  оператора; стоимость строк в [А-16](../../stage3-risk-cost/16-tco.md).
- (−) Разные возможности managed в облаках → feature-flag на уровне
  инфраструктуры (например, версии OpenSearch) — добавляет проверок в CI.

**Связи**: ADR-002 (портируемость), ADR-004 (Kafka), ADR-008 (ClickHouse),
ADR-003 (PII); NFR-09/NFR-11; риск T-07, T-09.
