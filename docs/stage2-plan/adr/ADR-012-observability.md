# ADR-012: Единая наблюдаемость — OpenTelemetry → метрики/логи/трассы

**Статус**: Принято · Этап 1
**Контекст**:
- АК-3 ([А-08](../../stage1-concept/08-quality-attributes.md)): MTTD ≤ 5 мин,
  MTTR ≤ 30 мин в двух облаках и 11 доменах.
- NFR-07: 100 % сервисов с телеметрией; T-05: PII не должны попадать
  в логи и метрики.
- Практика `15.6`: разработаны метрики, подходы к централизованному
  сбору логов и стратегия хранения — используется здесь дословно.

**Решение**:
1. **OpenTelemetry SDK** в каждом сервисе (traces + metrics + logs
   context): единый формат, без привязки к вендору облака (ADR-002).
   `trace_id` пробрасывается через HTTP и Kafka (пропагация в ключе
   сообщения) — сквозная трасса «клиент → домены → внешние интеграции».
2. **Метрики**: Prometheus в каждом регионе + глобальный агрегатор
   (Thanos-модель): SLI/API, лаги Kafka, бизнес-счётчики (Ц-1/Ц-2 —
   те же 5 бизнес-метрик, что в практике `15.6` — вовлечённость,
   конверсии, доставка уведомлений).
3. **Логи**: централизованный сбор (агенты узлов → буферизация в
   Kafka → роутер → горячий индекс 14 дней → холод Parquet в S3
   годами) — стратегия и объёмы из `15.6`. **PII-фильтр на агенте**
   до отправки: персональные идентификаторы заменяются псевдонимами
   (ADR-003).
4. **Трассы**: сэмплирование 100 % ошибок/пиковых операций, 1 %
   успешных (стоимость — TCO).
5. **Алерты и дашборды**: по SLI и бизнес-метрикам (не по CPU);
   дашборд «incident»: метрика → лог по trace_id → трасса. Корреляция
   через `trace_id` в логах.
6. Доступ к телеметрии — через ролевую модель (SRE/разработчики домена),
   журналы доступа — в аудите (АК-2).

**Последствия**:
- (+) Одна картина для 2 облаков: провайдерские нативные мониторинги —
  только дополнение, не основа (портабельность).
- (+) Диагностика «по цепочке» без логинов в пять консолей (АК-3).
- (+) Бизнес-метрики целей живут рядом с техническими — проверка Ц-1/Ц-2
  в одном месте.
- (−) Объём данных: хранение и индексация логов — реальная статья TCO
  ([А-16](../../stage3-risk-cost/16-tco.md)): ограничивается
  классификацией уровней, retention и сэмплированием трасс.
- (−) Дисциплина в коде: без спана/структурированного лога — слепота;
  закрывается шаблоном сервиса и чек-листом ревью (входит в критерии
  выхода фазы [А-06](../../stage1-concept/06-roadmap.md)).

**Связи**: АК-3, NFR-07; [А-14d](../views/infrastructure.md) (Операционный
контур); ADR-003 (PII-фильтр), ADR-004 (пропагация trace в событиях);
практика `15.6` (схемы логов и хранения).
