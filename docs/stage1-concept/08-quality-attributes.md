# А-08. Основные атрибуты качества

> Этап 1 · Утверждение концепта. По регламенту — **не более трёх основных**
> атрибутов; каждый отдельный участок архитектуры может иметь свои
> дополнительные, равномерного влияния на всё не бывает — компромиссы зафиксированы.

## АК-1. Масштабируемая доступность

**Почему основной**: особенность 2 (соревнования с большим числом
участников) + глобальность: отказ в прямом эфире виден всем сразу и
бьёт по Ц-1/Ц-3.

| Параметр | Значение |
|----------|----------|
| Доступность сервиса | 99,9 % в месяц (простой — не более 43 мин/мес) |
| Эластичность | рост ×10 от базовой нагрузки за ≤ 3 мин (KEDA по CPU/очереди) |
| Пик соревнования | 100 тыс. участников × 0,2 позиции/с = 20 тыс./с, design target 50 тыс./с |
| Приём результатов | не прерывается никогда (приоритетная деградация: промо → подсказки → приём) |

**Сценарии (формат источник→стимул→среда→реакция→мера)**:
1. Участники → одновременный старт в соревновании → пиковый час →
   автоскейл подов и шардов Redis, очередь Kafka впитывает → p95 приёма ≤ 500 мс.
2. Регион → отказ пода → обычный режим → переключение GSLB, реплика
   читает → восстановление чтения ≤ 60 с (бизнес-сессии не рвутся).

**Где адресуется**: ADR-004 (очереди как буфер), ADR-008 (шардирование
лидербордов), А-14c, А-14d.

## АК-2. Приватность и безопасность данных

**Почему основной**: особенность 5 («особое внимание охране данных»),
данные о здоровье — специальная категория GDPR (Art. 9), дети на площадке;
доверие — часть бренд-образа (Ц-4).

| Параметр | Значение |
|----------|----------|
| Соответствие | GDPR (в т.ч. Art. 9), локальные законы регионов, возрастные ограничения |
| Data residency | персональные данные пользователя — только в регионе его проживания |
| Шифрование | at rest (KMS) и in transit (TLS 1.3, mTLS для интеграций) |
| Доступ инженеров | JIT через брокер, запись сессии; прямого доступа к PII нет |
| Запрос пользователя | выгрузка ≤ 30 дней, удаление производных ≤ 7 дней |

**Сценарии**:
1. Пользователь → меняет согласие/просит удаление → обычный режим →
   домены получают событие очистки, кэши и индексы вычищаются → 7 дней.
2. Атакующий → скрейпинг/перебор через API → боевой режим → WAF, квоты,
   аномалии в SIEM → блокировка ≤ 1 мин, нет выгрузки PII.

**Где адресуется**: ADR-003, ADR-009, ADR-010, А-14e,
наработки `12.5`.

## АК-3. Наблюдаемость

**Почему основной**: 2 облака, 3 региона, 11 доменов — без единой картины
нельзя ни дежурить, ни считать стоимость (А-16), ни подтверждать АК-1.
Основа — практика `15.6`.

| Параметр | Значение |
|----------|----------|
| MTTD | ≤ 5 мин для инцидентов уровня P1 (алерты по SLI) |
| MTTR | ≤ 30 мин для P1 (сквозная диагностика: метрика → лог → трасса) |
| Полнота | 100 % сервисов с OTel-трассами, ротация trace_id в логах |
| Хранение | горячие логи 14 дней, холод — годами (Parquet/S3), PII отфильтрованы на агенте |

**Сценарии**:
1. Инженер → алерт «рост 5xx на шлюзе» → боевой режим → dashboards
   (метрики/логи/трассы по 15.6) → первопричина видна ≤ 10 мин.
2. Финансы/эксплуатация → запрос «почему вырос счёт» → плановый режим →
   метрики по доменам и регионам → расшифровка статьи TCO (А-16).

**Где адресуется**: ADR-012, схема логов из `15.6`, А-14d.

## Дополнительные (участковые) атрибуты

| Атрибут | Область | Мера | Не главный потому что… |
|---------|---------|------|------------------------|
| Отзывчивость | Мобильный UI, лента, статистика | p95 ≤ 300 мс, лента ≤ 500 мс | Важна, но локальна: закрывается CDN/кэшами/BFF, не требует глобальных решений |
| Офлайн-доступность | Клиент Activity | работа без сети ≥ 24 ч | Важна для сценария, но решается на клиенте (ADR-006) |
| Локализация | Контент, интерфейс | 30+ языков, RTL, региональные шаблоны | Покрывается процессом локализации (NFR-05), не архитектурным разломом |
| Целостность данных | События, синхронизация | дубли ≤ 0,01 %, 0 потерянных тренировок | Следствие АК-1/АК-2 в деталях (А-14c) |
| Стоимость владения | Инфраструктура | $/MAU-месяц (А-16) | Компромиссный атрибут: управляется TCO, не «свойство продукта» |
| Поддерживаемость | Команды | время выхода фазы ±10 % | Обеспечивается процессом (ADR-процесс, GitOps) |

## Компромиссы (обязательная часть пункта)

| Компромисс | Решение |
|------------|---------|
| АК-1 (эластичность) ↔ стоимость | Буферы Kafka и автоскейл экономят на постоянном «холодном» запасе; компенсируется в А-16 горизонтальной моделью |
| АК-2 (residency) ↔ АК-1 (единый пул) | Данные разрезаны регионами → лидерборды глобальные живут в обезличенном виде, персональная часть — в регионе |
| АК-2 ↔ отзывчивость | PII-хранилище добавляет обращение — терпимо: оно в тёплом пути только при загрузке профиля/настроек |
| АК-3 (полные логи) ↔ АК-2 и стоимость | PII-фильтр на агенте + классификация и retention (15.6) вместо «логировать всё навсегда» |
