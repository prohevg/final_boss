# А-03. Анализ стейкхолдеров и их интересов

> Этап 1 · Утверждение концепта.

## Карта стейкхолдеров

Влияние: **Высокое** — решает/блокирует; **Среднее** — участвует;
**Низкое** — затронут. Интерес: какую выгоду/какой риск несёт.

| Стейкхолдер | Интерес | Влияние | Ожидания от архитектуры | Риск при игнорировании |
|-------------|---------|---------|-------------------------|------------------------|
| Менеджмент (спонсор) | Новые каналы продаж, рост базы, образ бренда | Высокое | Понятная декомпозиция целей в roadmap, прогнозируемая стоимость (А-16) | Проект теряет финансирование на этапе 2–3 |
| Продакт (социальный трек) | Вовлечённость, удержание, скорость экспериментов | Высокое | Независимое релизование социальных функций, фиче-флаги (11.5), A/B | Эксперименты тормозят, конкуренты обгоняют |
| Продакт (коммерческий трек) | Конверсия в покупки (Ц-2) | Высокое | Стабильный мост в приложения компании, атрибуция кликов (ADR-010) | Цель Ц-2 недостижима технически |
| Маркетинг и региональные менеджеры | Релевантные промо по регионам, запуск новинок | Среднее | Гибкость таргетинга без релизов (промо-движок), региональные сегменты (FR-08, FR-11) | Пустые/общие баннеры, жалобы, отток |
| Команды существующих приложений (магазин, виды спорта) | Не потерять свои метрики и SLA, не усложнить свои API | Высокое | Публичный контракт API/SDK, mTLS, версионирование, изоляция сбоев | Деградация продаж основного канала |
| Юристы / DPO | GDPR (Art. 9 — данные о здоровье), детские данные, локальные законы | Высокое | Data residency, PII-хранилище, согласия и выгрузка/удаление (ADR-003, FR-15) | Штрафы, блокировка запуска в регионе |
| Информационная безопасность | Атаки на интеграции, переборы, утечки | Высокое | WAF/квоты, mTLS, KMS, JIT-доступ (12.5, А-14e) | Инцидент → репутационные потери Ц-4 |
| SRE / инфраструктура | Управляемость 2 облаков, дежурства, восстановление | Высокое | GitOps, единая наблюдаемость (15.6), DRP (14.5), портируемое ядро (ADR-002) | Рост стоимости и «ночных» инцидентов |
| Данные / ML | Качественные события, доступ к данным в рамках согласий | Среднее | Событийная шина, озёра аналитики, обезличивание (ADR-004, ADR-012) | Персонализация невозможна или нелегальна |
| Разработчики (40–60, распределённые, мультиязычные) | Понятные границы сервисов, независимость команд | Среднее | Домены = владение данными, стандартные шаблоны сервисов (ADR-001) | Размывание ответственности, конфликты релизов |
| Поддержка пользователей | Разбор обращений: что произошло с тренировкой/данными | Низкое | Сквозные trace_id, аудит действий, экспорт данных (15.6) | Долгие разборы, недовольство пользователей |
| Модераторы/сообщество | Безопасный контент в группах | Низкое | Инструменты модерации, приоритеты очередей | Токсичность → отток (Ц-1) |
| Пользователи: любители (основной сегмент) | Простота, прогресс «сравнение с собой», друзья | Среднее (через метрики) | Отзывчивость p95, офлайн, понятные сравнения | Низкий retention (Ц-1) |
| Пользователи: профессионалы | Точные данные устройств, детальные разборы | Низкое | Поддержка BLE-устройств, экспортируемость (FR-09) | Недовольство «игрушкой» у амбассадоров |
| Пользователи и родители: дети на площадке | Безопасность, возрастной контент, приватность по умолчанию | Низкое (но юридически высокое) | Возрастной режим, минимальная видимость, согласие родителя (FR-15) | Юридические последствия (NFR-04) |
| Внутренний инвестор (этап 3) | Окупаемость, контролируемые риски и расходы | Высокое | Подтверждённые риски (А-05, А-15) и TCO (А-16) | Отказ на защите этапа 3 |

## Анализ влияния и стратегия работы

- **Высокое влияние + высокий интерес (управлять вовлечённо)**: менеджмент,
  продакты, существующие приложения, DPO, ИБ, SRE. Участвуют в согласовании
  ADR; их вето-темы зафиксированы как ограничения в [А-09](09-nonfunctional-requirements.md)
  и [А-10](10-architecture-options.md).
- **Высокое влияние + низкий интерес (держать в курсе)**: юристы по детским
  данным, поддержка — регулярные статусы, но без вовлечения в детали.
- **Низкое влияние + высокий interest (информировать)**: разработчики,
  данные/ML — участвуют через ADR-процесс и шаблоны.
- **Низкое влияние + низкий интерес (наблюдать)**: модераторы — потребность
  проявится в фазе 1, инструменты заложены в Social-домен.

## Конфликты интересов (и как разрешены)

| Конфликт | Разрешение (где описано) |
|----------|--------------------------|
| Маркетинг хочет «пуш всем» ↔ приватность и отток | Сегментация и квоты уведомлений, opt-in по типам (FR-15); риск B2 в [А-05](05-risks.md) |
| Существующие приложения не хотят лишней нагрузки | Мост только через их публичный API с квотами и circuit breaker (ADR-010, из 10.5) |
| Продакт хочет быстро менять промо ↔ безопасность | Параметризованный промо-движок без релизов, контент проходит модерацию |
| SRE хочет меньше облаков ↔ бизнес выбрал best-of-breed облака | Портируемое ядро и единый GitOps-контур (ADR-002), TCO считает обе модели (А-16) |
| ML хочет все данные ↔ согласия | События обезличиваются на агенте, PII-хранилище отдельно (ADR-003, ADR-012) |
